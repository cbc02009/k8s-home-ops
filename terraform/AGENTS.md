# terraform/ — OpenTofu projects

- **OpenTofu, not Terraform.** HCL files are `*.tofu` (formatter: the VS Code `opentofu` extension, format-on-save; `files.associations` maps `*.tofu` → opentofu). Use the `tofu` CLI.
- Projects:
  - `cloudflare/` — provider (`main.tofu`), one zone file per domain (`ctec_run.tofu`, `kokoro_wtf.tofu`, `cnas_dev.tofu`), and the shared `modules/cf-zone/` module (resolves zone by name via `data.cloudflare_zone.filter`; takes a `records` map). Import blocks live in a single `imports.tofu` file — delete it after the first apply. Records owned by external-dns (`k8s.*` TXTs, proxied tunnel CNAMES) and cert-manager (`_acme-challenge.*` TXTs, stale dated DKIM selectors) are intentionally NOT in tofu — do not add them.
  - `authentik/` — identity provider configuration: applications, flows, stages, directory, customization (`modules/`, `expressions/`).
  - `garage/` — Garage object storage (backs dragonfly/opencloud in the cluster).
- **Secrets**: `terraform/secrets.sops.yaml` (age, user key) is decrypted to the environment by `terraform/.envrc` (`use_sops`); the age key file itself is exported by the repo-root `.envrc` (`~/.config/sops/age/keys.txt`). Never write secret values into `.tofu` files.
- **State**: PostgreSQL backend (`terraform` database on the cnpg cluster, one schema per project: `cloudflare`, `authentik`, `garage`). Credentials come from `PGUSER`/`PGPASSWORD` in the environment (decrypted from `secrets.sops.yaml` by `.envrc`). Never commit state or plan files.
- **In-cluster runs**: `terraform/` is also reconciled by tofu-controller (`kubernetes/apps/flux-system/terraform/`, one `Terraform` CR per project). The controller plans on every push to `main` but **does not auto-apply** — plans wait for manual approval. Until `approvePlan: auto` is enabled, apply in-cluster with `kubectl -n flux-system patch terraform <name> --type merge -p '{"spec":{"approvePlan":"<plan id>"}}'` (plan id from the CR status), or keep applying locally from this directory; state is shared, so both paths converge on the same state. The runner gets credentials from the `terraform-secret` ExternalSecret (1Password items `1password` and `postgres`).
- **DNS coordination**: some records are also managed in-cluster by external-dns (`kubernetes/apps/network/external-dns`, Cloudflare + UniFi variants). When adding/removing hostnames, check both sides and avoid conflicting the two managers on the same record.
